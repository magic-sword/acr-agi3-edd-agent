## 実装した動作

提出経路は `MyAgent → DeliberativeGamePlayer → SkillHarness / ADK SkillToolset`。
PLAN・CAUSAL・EXPERIMENT・EXECUTE・REVIEWの境界と、オンデマンドの観測スキルを維持した。

クリックは次の順序に限定する。

1. `game-controller`をロードし、`move_cursor(x, y, reasoning)`で内部照準を移動する。ゲーム手数は消費しない。
2. `visual-inspector`の`observe_screen`で照準付き画像を取得し、目標との位置関係を確認する。全モードで観測・cropが可能。
3. EXPERIMENTまたはEXECUTEで`click_at_cursor(visual_evidence, reasoning)`を呼ぶ。ここでは座標を変更できない。
4. ゲートウェイから次のフレームを受け取ったら、REVIEWで予測と実際の結果を比較する。

確認はフレームIDとカーソル更新番号に紐付く。移動後の未観測、古いフレーム、照準を含まないcrop、前フレームだけの観測ではクリックできない。再移動・新しい盤面・リセットで確認は失効する。モデルに直接座標クリックは公開しない。確認前はクリック確定ツールのスキーマも非公開とし、確認後だけ公開する。

これは観測手順を保証するもので、VLMの位置認識や`visual_evidence`の正しさまで保証するものではない。

## 因果推論とモデル入力

- ガイダンスはロード済みスキル、観測状態、記録済み目標、実験結果、照準確認状態を区別する。
- ADKの正式なbefore/after tool callbackで、ロード後も最新ガイダンスを返す。同じセッション内の再ロードでは本文を重複注入しない。
- 重複した未解決質問を積み重ねない。支持/反証/不明の結果を参照し、条件付きルールの記録と計画への復帰を案内する。
- 実験時に`expected_visual_change`を真偽値で宣言し、原フレームの変化と矛盾する支持判定はREVIEWに留めて拒否する。変化がないことを予測した実験も扱える。これは必要条件の検査であり、HUD変化などを目的達成の証明にはしない。
- 同一盤面・同一介入の再実験には`retry_reason`が必要。状態が変わる正当な連続移動は一律禁止しない。
- 自由文からの操作推定、未公開ツールの別ツールへの置換、文字列による支持/反証の補完を除去。
- 最新の明示的観測を一組だけモデルに渡し、フレーム・crop・照準のラベルと最新ガイダンスを添える。直近10メッセージへの無条件切り捨ては廃止。入力トークン予算超過は明示的に失敗として記録する。
- 重みが見つからない評価を暗黙のモックへ置き換えない。テストは明示的な生成関数を使う。
- Dataset内へのログ書き込みをモジュールimport時に行わない。

実観測に色ID12が含まれることを確認した。ゲーム画面はインストール済み公式`arc_agi.rendering.COLOR_MAP`の16色を使用する。従来の10色レンダラーは別用途の呼び出し用に残し、`ScreenTools`がゲーム用パレットを明示する。未定義色は黒に潰さず拒否する。比較画像には同じ内部照準を重ね、照準の追加をゲームの変化と誤認させない。

## 評価記録

`run_local_leaderboard.py`は公式SDKのOFFLINEモードを明示し、提出ノートブックと同じクラスを直接importする。ノートブックの任意セル実行と例外を握り潰すフォールバックは廃止。

`logs/runs/<run_id>/`に実行manifestと環境別JSONを保存する。環境別記録には実手数、終了理由、例外スタック、失敗した推論のツール履歴、原フレーム、最終思考状態、モデル情報を含む。成功した各行動にもツール履歴とモデルの生出力・画像数・入力トークン数を記録する。モデルの生出力は判断を説明する観測資料として保存し、操作へ再解釈しない。ゲームAPIへ送るreasoningは16KB制限内の短い理由とモード情報に限定し、詳細なツール履歴は送信しない。思考スナップショットは後続の更新で変化しないコピーとして保存する。

モデルによる視覚レビューと、機械的なマスク予測の一致率は別指標とする。既存EDDの画素差ベース診断を攻略進捗と同一視しない。推論エラーは手数上限による終了と区別する。

既存ログを保持して検証する例:

```bash
docker exec -w /workspace arc-agi3-dev python3 scripts/run_local_leaderboard.py \
  -g ft09 -s 2 --output-dir /workspace/logs/verification_cursor
```

汎用EDDコアは変更していない。評価スクリプトでARC固有の観測と終了結果を保存する。

## 検証と残る範囲

- 変更した各スキルの正例3件・負例3件を`tests/test_verified_observation_loop.py`で検証する。
- ADK経由のロード、観測、照準確認、行動、レビュー、計画復帰を関連統合テストで確認する。
- 全体テストと3スキルの既存契約、計227件が合格。
- game-controller、visual-inspector、causal-deliberationは`edd_validate_skill`とskill-creatorの検証に合格。EDDのエラー0・警告0。

逆算計画の汎用探索器、条件付きマクロ合成の再構築、知覚結果の完全な構造化と独立した予測検証は、この変更では実装していない。未接続の旧プレイヤーや補助スクリプト全体の刷新も行っていない。今回の修正対象は実際の提出経路と、その観測・操作・レビュー・計測の整合性である。

実モデルによる攻略性能は、契約テストの合格とは別に評価する。短いFT09確認は全体リーダーボード評価の代替ではなく、スコア改善を保証しない。

この実行で、変化がないのにモデルが移動を支持したことを受け、上記の明示的な画面変化予測と矛盾検査を追加した。最終版の検査は変更あり／なしの支持・拒否、および不明判定への復帰を自動テストで確認した。検査追加後の実モデル再評価は未実施。目標位置の幻覚や対象の意味的な認識精度は、この必要条件の検査だけでは解消しない。
